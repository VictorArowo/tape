# tape site

Static marketing site for tape. No build step: serve this folder as-is.

```sh
python3 -m http.server 8770 --directory site
```

## Result data

The results sections read JSON from `data/results/`:

- `honest-vs-naive.json`: **real.** Generated by the engine, then copied in:

  ```sh
  cargo run --release -p tape-cli -- compare --from 2024-01 --to 2024-12 --json results/honest-vs-naive.json
  cp results/honest-vs-naive.json site/data/results/
  ```

- `experiment.json`: **real.** The full lab run (200 attempts), copied in:

  ```sh
  cp results/lab/full-1/experiment.json site/data/results/
  ```

  Some copy under the scatter chart is written for this run specifically (the note about
  high-turnover strategies and the buy-and-hold-in-disguise cluster). Revisit it if the
  run is replaced. Model knowledge cutoffs live in `MODEL_CUTOFFS` in `results.js`.

  Small real runs can be published with `"pilot": true` added, which shows a
  "Pilot run" badge instead.

## Demo engine

The "Run a backtest" demo runs tape's real engine, compiled to WebAssembly, in `engine/`:
`tape.wasm`, the `tape-engine.js` loader, `tape-worker.js` (every run happens in a Web
Worker, stopped after 10 seconds), `strategies.js` (the editor's example strategies), and
one data file per month of 2024 in `engine/data/` (loaded on first use). The four code
files must be copied together. Rebuild them from the repo root with:

```sh
./web/build.sh site/engine
```

Visitors' own strategies ("Write your own") only run from the editor, when they press Run.
Never load strategy code from a URL and run it automatically.

`engine/check.html` is a self-test page the build writes; it's gitignored so it isn't deployed.

Do not launch the site while any placeholder flag is visible.

`data/btcusdt-2024-01-03.json` is real: one-minute closes from Binance's public archive.
